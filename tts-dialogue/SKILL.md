# 雙人對話配音

短劇、對話、兩個角色互動的內容——**一次合成，不要分開配。**

---

## 🔴 為什麼不准分開配再剪接

2026-08-24 EP10 Short 實測踩過：把兩個角色**各自單獨配音**，再用 whisper 的 cue 邊界切開拼起來，
結果**前一句的尾音被帶進下一句**，實聽出現「都是都是」這種重複。

根因：**whisper 的 cue 邊界是「字被辨識出來的位置」，不是「聲音停止的位置」**，
尾音會超出 cue 結尾約 0.25 秒。

Gemini TTS **原生支援最多 2 個說話者**：一次呼叫給整段對話，
模型自己處理輪替、呼吸、語氣互動——**這是剪接永遠做不到的**。

⚠️ 同樣的道理：**旁白要改就重錄，不要剪接。** 重錄只要幾美分，比修便宜。

## 用法

```bash
GEMINI_API_KEY=<key> automation/tts_dialogue.py \
  <順序.tsv> <輸出前綴> \
  --a 皮可:Orus \
  --b Hermes:Achernar \
  --style "<語氣指示>"
```

### 順序檔格式（TSV，用真正的 Tab 分隔）

```
1	皮可	今天我多了一位新同事 她叫 Hermes
2	Hermes	你好~
3	皮可	從安裝到上線 都是我弄的
```

| 欄 | 內容 |
|---|---|
| 1 | 序號（純粹給人看，不影響合成）|
| 2 | **說話者名字**——必須跟 `--a` / `--b` 的名字**完全一致** |
| 3 | 台詞 |

---

## 音色

| 角色 | 音色 | 備註 |
|---|---|---|
| 皮可（主持人）| `Orus` | Short 用。長片旁白用 `Iapetus` |
| Hermes | `Achernar` | 女聲，與皮可區隔明顯 |

環境變數：`TTS_MODEL`（預設 `gemini-2.5-pro-preview-tts`）、`TTS_PITCH`（預設 `-1`）、`TTS_TEMPO`。

---

## 硬規則

1. **最多兩個說話者。** 超過兩個 Gemini 不支援，要拆段或改設計。
2. **說話者名字要一致**：tsv 第 2 欄 ↔ `--a`/`--b` 的名字。不一致模型會分不清誰是誰。
3. **一次給整段**，不要一句一句呼叫再拼——那就退化成剪接了。
4. **合成後先聽審再進剪輯。** 技術指標乾淨 ≠ 好聽；咬字、斷句、怪音要用耳朵抓。
5. **付費 API**：動手前先報「跑什麼＋估多少錢」，取得明確同意。

## 常見錯誤

| 症狀 | 原因 | 解法 |
|---|---|---|
| 出現重複的字（「都是都是」）| 分開配再剪接 | 用本 skill 一次合成 |
| 兩個角色聲音分不清 | tsv 名字與參數不符 | 對齊名字 |
| 合出來 0 句／空檔 | tsv 不是真正的 Tab 分隔 | 檢查分隔字元 |
| 語氣太平 | 沒給 `--style` | 寫明情境與情緒 |

---

## 什麼時候**不要**用這支

- **單人旁白**（教學長片）→ 用 `tts_pipeline.py`
- **三人以上** → Gemini 不支援，要重新設計
