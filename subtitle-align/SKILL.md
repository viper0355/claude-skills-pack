# 字幕強制對齊

把「配音檔 ＋ 正確逐句文字」對成一份**時間準、零錯字**的 SRT。

---

## 🔴 核心觀念：這不是語音辨識

**ASR 只用來抓「時間」，文字一律用你提供的。**

流程是：faster-whisper 取**逐詞時間碼** → 與已知正確文字做**字元序列比對映射** → 每句配起訖時間。

所以就算 whisper 聽錯字，字幕內容也不會錯——它只借時間。
這就是叫「**強制對齊**」而不是「辨識」的原因。

⇒ **不要**拿 whisper 直接轉錄當字幕，錯字會進成品。

---

## 用法

```bash
uv run --with faster-whisper automation/align_srt.py \
  <音檔.mp3> <逐句文字.txt> <輸出.srt> [模型]
```

| 參數 | 說明 |
|---|---|
| 音檔 | 配音 mp3／wav |
| **逐句文字** | 純文字，**一行一句**，內容要與音檔**完全一致** |
| 輸出 | 產生的 SRT |
| 模型 | 預設 `medium`（cpu／int8）。要更準用 `large-v3`，更慢 |

### 逐句文字怎麼來

- 長片：TTS pipeline 會自動產 `<輸出>-旁白文字.txt`
- 雙人對話：從順序 TSV 抽第三欄
  ```bash
  cut -f3 順序.tsv > 旁白文字.txt
  ```

**一行一句**很重要——它決定 SRT 的斷句。想讓某句自己一張字幕，就讓它自己一行。

---

## 硬規則

1. **文字必須與音檔一致。** 改了旁白就要同步改這份文字，否則對齊會整段歪掉。
2. **一行一句**，不要一行塞兩三句。
3. **全形標點會被忽略**（比對時會濾掉標點與空白），但保留在輸出的字幕裡。
4. 語言固定 `zh`。其他語言要改腳本。

---

## 🔴 whisper 的 cue 邊界不能拿來剪音檔

**cue 的結束時間是「字被辨識出來的位置」，不是「聲音停止的位置」**——
尾音會超出 cue 結尾約 **0.25 秒**。

所以：

| 想做的事 | 可不可以 |
|---|---|
| 用 cue 當**字幕**時間軸 | ✅ 可以，這就是它的用途 |
| 用 cue 當**畫面**時間軸 | ✅ 可以 |
| **照 cue 把音檔切開再拼** | ❌ **絕對不要**，會把前一句尾音帶進下一句 |

要改旁白就**重錄**，不要剪接。雙人對話用 `tts-dialogue`（Gemini 原生 multi-speaker 一次合成）。

---

## 快取

以「音檔 mtime ＋ size ＋ 模型」為 key 快取 ASR 結果。
**同一個音檔重跑不會重轉錄**，改逐句文字重對齊很快。

⇒ 想調整斷句時，直接改文字檔重跑即可，不必等 ASR。

---

## 驗收

```bash
grep -c '^[0-9]\+$' 輸出.srt          # cue 數，要等於逐句文字的行數
tail -4 輸出.srt                      # 最後一句的結束時間
ffprobe -v error -show_entries format=duration -of csv=p=0 音檔.mp3
```

| 檢查 | 標準 |
|---|---|
| cue 數 | **等於**逐句文字的行數 |
| 最後 cue 結束時間 | 不超過音檔長度 |
| 首句起始 | 通常 < 1 秒，太晚代表對歪了 |
| 抽查中段幾句 | 時間與實際講到的位置相符 |

**對不上就先檢查逐句文字跟音檔是不是同一版**，那是最常見的原因。

## 兩種 SRT 的用途

| 版本 | 用途 |
|---|---|
| **句級**（本工具產出）| 上傳 YouTube 當 CC |
| **頁級**（每頁一到兩行）| **燒進畫面的內嵌字幕**——約 9 成觀眾不開 CC |

內嵌字幕要另外把句級轉成頁級，不要直接拿句級燒。
